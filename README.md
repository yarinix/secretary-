# Secretary Bot

Секретарь для Telegram Business: **пересылает вам копию каждого входящего сообщения** и отвечает клиенту в ваших личных чатах от вашего лица. Если вы сами ответили в чате, бот там временно замолкает. Управляется из Telegram Mini App на том же домене.

## Как работает

- Клиент пишет → вы получаете `📨` с копией → бот отвечает через каскад моделей Gemini → вы получаете `🤖` с копией ответа (можно отключить).
- Копия входящего приходит **всегда**, даже если автоответы выключены, бот на паузе, сработал лимит, нет права отвечать или не задан ключ ИИ.
- Обрабатываются текст, подписи, голосовые, видеосообщения (кружки) и фото. Стикеры и документы не отвечаются, но копия входящего приходит.
- Управление: **Mini App** (кнопка «Настройки» в меню бота) или команды в личке — `/business on|off`, `/business inbox on|off`, `/business notify on|off`, `/business persona <текст>`, `/business persona clear`, `/business status`.
- Логика перенесена из [ForUs](https://github.com/yarinix/ForUs-) (`tgbot/business.py`, `tgbot/llm.py`): пауза при вашем вмешательстве, лимит ответов в час на чат, защита от инъекций в промпте, каскад моделей.

### Каскад моделей

Тот же, что в ForUs: `gemini-3.5-flash-lite` → `gemini-3.1-flash-lite`. При `429` / исчерпании квоты бот сразу переходит к следующей модели; при временных сбоях (5xx, таймаут, обрыв связи) делает до 3 попыток на той же модели; пустой ответ считается неудачей. Список и его порядок задаётся в Mini App, дефолт — через `GEMINI_MODELS` (модели через запятую). SDK `google-genai` не нужен — запросы идут через уже имеющийся `aiohttp`.

> **Про `ANTHROPIC_API_KEY`:** Claude не подключён. Название переменной оставлено исторически (в Render уже так задано, переименовывать лень) — **в ней лежит ключ Gemini**. Можно дополнительно задать «правильное» имя `GEMINI_API_KEY`: если заданы оба, приоритет у `GEMINI_API_KEY`. Код вызовов `api.anthropic.com` удалён.

Если ключа нет вообще, бот **не отправляет собеседнику ничего**: сообщение «от лица владельца» о технической ошибке выглядело бы странно. Вы просто получите копию входящего и сможете ответить сами.

## Подключение

1. @BotFather → `/newbot`; затем Bot Settings → Business Mode → включить.
2. Нужен Telegram Premium. Настройки → Telegram для бизнеса → Чат-боты → выбрать бота, оставить право отвечать на сообщения.
3. Узнайте свой числовой ID (@userinfobot) и задайте `OWNER_ID` — **обязательно**. Бот не запустится без него: больше никто не сможет захватить управление через `/start`.
4. Задеплоить на Render (New → Blueprint → этот репозиторий), заполнить переменные.
5. После первого деплоя в меню бота появится кнопка «Настройки» → Mini App.

## Mini App — управление из Telegram

Тот же aiohttp-сервер, что и вебхук, отдаёт `/app` (на проде: `https://secretary-bot-htem.onrender.com/app`). `GET /` по-прежнему возвращает `ok`, `POST /webhook` остаётся за aiogram.

**Все функции `/business` перенесены в интерфейс**, плюс редактирование «переменных» без перезапуска: пауза **60 → 10 минут**, лимит ответов в час, размер истории, лимит persona, имя владельца, часовой пояс, игнорируемые ID, порядок моделей каскада.

| Что | Где меняется | Когда применяется |
|---|---|---|
| Автоответы, копии входящих/ответов, persona | UI → SQLite `settings` | сразу, к следующему сообщению |
| Пауза после вашего сообщения, лимит ответов | UI → SQLite | сразу, **в том числе к уже активной паузе** |
| История, лимит persona, имя, часовой пояс, игнорируемые ID | UI → SQLite | сразу |
| Порядок моделей каскада | UI → SQLite | сразу (объект `GeminiCascade` создаётся на вызов) |
| `BOT_TOKEN`, `OWNER_ID`, `WEBHOOK_SECRET`, `PORT`, `DB_PATH`, `BASE_URL` | только дашборд Render | после рестарта |
| Ключ Gemini (`ANTHROPIC_API_KEY` / `GEMINI_API_KEY`) | только дашборд Render | после рестарта |

Ключ Gemini **не показывается и не меняется** в UI — только индикатор «задан / не задан». Системные значения приходят в `/api/state` замаскированными и никогда не принимаются в `/api/settings`.

**Безопасность.** Каждый запрос к `/api/*` подписан `initData`: `secret = HMAC_SHA256("WebAppData", BOT_TOKEN)`, подпись — HMAC от отсортированного `data_check_string`, сравнение через `hmac.compare_digest`. Дополнительно проверяются свежесть `auth_date` (TTL 1 час, отсекаются будущие даты) и `OWNER_ID`. `initDataUnsafe` не используется. Подделанная подпись → `401`, чужой пользователь → `403`, невалидные поля → `400` с ошибками по конкретным ключам (сохранение all-or-nothing). Ответы идут с `Cache-Control: no-store`, тело запроса ограничено 64 КБ, секреты и `initData` не логируются и не сериализуются.

**Роуты:** `GET /app`, `GET /static/{app.css,app.js}`, `POST /api/state`, `POST /api/settings`, `POST /api/test-ai`. CORS не нужен — same-origin.

> ⚠️ На бесплатном плане Render диск **эфемерный**: настройки из UI лежат в SQLite и сбрасываются к env-дефолтам при перезапуске. Постоянные значения задавайте в Render — они же служат дефолтами для пустой базы. Для постоянного хранения подключите диск и задайте `DB_PATH`.

Ручная проверка после деплоя: открыть Mini App → поставить паузу **60 → 10** → написать себе в чат → бот замолчит на 10 минут без рестарта.

## Переменные окружения

| Переменная | Обязательная | Описание |
|---|---|---|
| `BOT_TOKEN` | да | токен от @BotFather |
| `OWNER_ID` | **да** | ваш числовой Telegram ID |
| `ANTHROPIC_API_KEY` | нет | **ключ Gemini** (историческое название, см. выше) |
| `GEMINI_API_KEY` | нет | «правильный» алиас; приоритет над `ANTHROPIC_API_KEY` |
| `GEMINI_MODELS` | нет | дефолт каскада через запятую; переопределяется в UI |
| `WEBHOOK_SECRET` | нет | секрет вебхука; если не задан, берётся хэш от `BOT_TOKEN` (не «change-me») |
| `WEBHOOK_BASE_URL` | нет | базовый URL вебхука; если не задан, используется автоматический `RENDER_EXTERNAL_URL` |
| `WEBAPP_URL` | нет | полный URL Mini App (с `/app`); если не задан, берётся `BASE_URL + /app` |
| `OWNER_NAME` | нет | как зовут владельца в промпте (дефолт для UI) |
| `BOT_TIMEZONE` | нет | часовой пояс (дефолт для UI), по умолчанию `Asia/Omsk` |
| `BUSINESS_TAKEOVER_MINUTES` | нет | пауза после вашего сообщения, 60 (дефолт для UI) |
| `BUSINESS_MAX_REPLIES_PER_HOUR` | нет | лимит ответов на чат, 20 (дефолт для UI) |
| `BUSINESS_IGNORE_IDS` | нет | ID через запятую (дефолт для UI) |
| `DB_PATH` | нет | путь к SQLite, по умолчанию `secretary.db` |
| `PORT` | нет | порт, по умолчанию 10000 |

Все пользовательские переменные объявлены в `render.yaml`; `WEBHOOK_SECRET` генерируется Render автоматически. `RENDER_EXTERNAL_URL` Render подставляет сам — если его не окажется, бот поднимется, но запишет предупреждение в лог и не получит обновления (поллинг-фолбэка нет). `render.yaml` намеренно не меняется: прод уже работает на Python 3.14 / aiohttp 3.14.5.

## Разработка

```bash
pip install -r requirements.txt
python -m unittest discover -s tests -v
```

92 теста покрывают чистые функции, сборку `contents` для Gemini, SQLite (включая WAL и атомарную запись), схему настроек и границы валидации, подпись `initData` и HTTP-роуты Mini App (401/403/400/413/415, отсутствие утечек секретов). aiogram, сеть и `BOT_TOKEN` тестам не нужны.

Структура: `config.py` (валидация окружения), `helpers.py` (чистые функции), `storage.py` (SQLite + RLock/WAL), `llm.py` (каскад Gemini), `app_settings.py` (схема настроек), `miniapp_auth.py` (`initData`), `webapp.py` (HTTP-роуты), `web/` (HTML/CSS/JS Mini App), `main.py` (aiogram-обработчики, webhook, сборка приложения).
